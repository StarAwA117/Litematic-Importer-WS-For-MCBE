# Litematic Importer WS For MCBE

一个通过 WebSocket 将 **Litematica** 建筑投影导入 **Minecraft 基岩版 (Bedrock Edition)** 的工具。

无需本地存档，可在任何正在运行的世界中直接导入大规模建筑，支持自动优化指令、实时进度监控和区域分割。

## 前置要求

- **Node.js** 18+
- Minecraft 基岩版（支持 WebSocket 连接的版本）

## 安装

```bash
git clone https://github.com/StarAwA117/Litematic-Importer-WS-For-MCBE.git
cd Litematic-Importer-WS-For-MCBE
npm install
```

## 使用方法

### 1. 启动服务

```bash
npm start
# 或指定端口
node litematic.js 8080
```

### 2. 连接游戏

在 Minecraft 基岩版聊天栏中输入：

```
/connect 127.0.0.1:8080
```

### 3. 放置 Litematic 文件

将 `.litematic` 文件放入项目目录下的 `litematic/` 文件夹。

## 终端命令

除了游戏内聊天栏，也可以在**运行脚本的终端**中直接输入命令（不需要 `/connect` 也能使用文件操作类命令）。

```
$list           # 查看建筑文件列表
$search 城堡    # 搜索建筑文件
$export 城堡    # 导出结构文件
$help           # 查看所有命令
exit            # 退出脚本
```

- 终端命令与游戏内命令完全相同，输入 `$` 前缀命令即可执行
- 需要游戏连接的操作（如 `$create` 查询坐标、放置方块）会自动委托给当前已连接的游戏；未连接时提示无法获取坐标
- 提示符为 `litematic>`，输入 `exit` 或 `quit` 退出

## 游戏内命令

所有命令以 `$` 为前缀，在聊天栏中输入。

### $create

导入一个 Litematic 文件。

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| 文件名 | string | 是 | litematic 文件名（可带或不带 `.litematic` 后缀） |
| X | int | 否 | 目标 X 坐标（留空则使用玩家当前位置） |
| Y | int | 否 | 目标 Y 坐标 |
| Z | int | 否 | 目标 Z 坐标 |
| 模式 | string | 否 | `trim`（默认）：裁剪底部空气层，建筑底部对齐放置点；`raw`：保留原始高度偏移 |

> **底部空气层说明**：Litematic 文件的区域高度通常包含大量空白空气（建筑底部可能悬空数层甚至几十层）。默认 `trim` 模式会自动检测并裁剪这些空气层，让建筑紧贴放置点地面，避免悬空和破坏地形。使用 `raw` 可保留原始偏移。

**示例：**

```
$create my_house
$create my_house 100 64 200
$create my_house 100 64 200 raw
$create "my house" raw
```

执行后会显示预览信息（尺寸、方块数、底部空气层、预计耗时），输入 `$y` 确认后开始导入。

### $preview

在不放置方块的情况下预览建筑的位置和轮廓（FMBE 风格虚拟预览）。

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| 文件名 | string | 是 | litematic 文件名 |
| X | int | 否 | 目标 X 坐标（留空则使用玩家当前位置） |
| Y | int | 否 | 目标 Y 坐标 |
| Z | int | 否 | 目标 Z 坐标 |
| 模式 | string | 否 | `trim`（默认）/ `raw`，同 `$create` |

预览效果：
- **粒子边框** — 建筑底部与四角的熔岩粒子轮廓（约每 4 秒刷新一次）
- **实体标记** — 8 个角点（`✦`）与边框点（`▪`）的悬浮标记，以及顶部信息标签，持续显示
- 聊天栏显示尺寸、实际放置范围与底部空气层数

> 实体标记使用 `text_display` 实体，需要 Minecraft 1.19.60+（粒子边框任意支持 WebSocket 的版本均可用）。

**示例：**

```
$preview my_house
$preview my_house 100 64 200
```

### $unpreview

清除当前建筑预览（移除所有标记实体并停止粒子刷新）。

```
$unpreview
```

### $export

将 Litematic 导出为 Minecraft 基岩版结构文件 `.mcstructure`，可在游戏内用结构方块预览和放置。

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| 文件名 | string | 是 | litematic 文件名 |
| 导出名 | string | 否 | 导出文件名（默认与 litematic 同名） |
| 模式 | string | 否 | `trim`（默认）/ `raw`，同 `$create` |

导出文件写入项目目录的 `structures/` 文件夹。使用方式：

1. 将 `.mcstructure` 文件放入行为包的 `structures` 文件夹（如 `BP/structures/mystructure/`）或单机存档的 `structures` 文件夹
2. 游戏内用结构方块加载预览，或执行 `/structure load <名称>`

**示例：**

```
$export my_house
$export my_house castle
$export my_house castle raw
```

### $list

查看 litematic 文件列表。

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| 页码 | int | 否 | 指定页码（每页 5 个文件，默认第 1 页） |

**示例：**

```
$list
$list 2
```

### $search

按关键词搜索建筑文件。

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| 关键词 | string | 是 | 搜索关键词（不区分大小写） |
| 页码 | int | 否 | 指定页码 |

**示例：**

```
$search castle
$search house 2
```

### $y

确认待执行的导入操作。在 `$create` 显示预览后使用。

### $n

取消待执行的导入操作，或中断正在进行的导入。

### $verify

检查任务（`$create` 返回的任务 ID）对应的建筑在游戏世界中的状态。**默认检查游戏世界与投影的方块一致性**（被挖掉/替换的方块会被检测出来）。

> **方块映射说明**：Litematica 文件使用 Java 版方块 ID（可能来自各类 mod），导入前会通过 `generator_blocks.json` 映射为基岩版方块。无法映射的方块（如 mod 专属方块）在导入时会被**跳过**（视为空气）。使用 `$verify <ID> map` 可以提前检查这些方块。

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| ID | int | 是 | 任务 ID（`$create` 成功后显示） |
| 模式 | string | 否 | `world`（默认，可省略）= 检查游戏世界与投影的方块差异（需游戏连接，逐块比对，`$n` 可中断）；`map` = 检查方块映射错误（无需连接） |

**示例：**

```
$create my_house        # 显示: 任务ID: 1
$verify 1               # 默认检查游戏世界与投影一致性（需先 /connect 连接游戏）
$verify 1 world         # 同上（world 可省略）
$verify 1 map           # 检查任务 1 的方块映射错误
```

世界检查无差异时显示：

```
世界检查完成 (任务 #1) 已逐块 testforblock 比对 N 个方块，全部与投影一致
```

发现被挖掉/替换的方块时显示报告（前 20 条，坐标 + 期望方块）：

```
=== 世界检查报告 (任务 #1) ===
文件: my_house.litematic
检查: 1000 个方块 | 不匹配: 3 个 耗时 12.5s
(100, 64, 200) 期望 stone
(101, 64, 200) 期望 oak_planks
...
发送 $fix 1 可重新放置这些方块，恢复与投影一致
```

> 本检查只检测被挖掉/替换的方块，不检测玩家额外新增的方块（空气位置不检查）。
>
> 服务器繁忙时会**限流丢弃命令**（无响应），检查/修复会自动超时重试（最多 3 次）以避免误报。

映射检查（`map` 模式）有错误时显示报告（文件、无法映射方块数量、各方块名 × 数量清单），例如：

```
=== 方块检查报告 (任务 #1) ===
文件: my_house.litematic
无法映射方块: 12 个 (导入时会被跳过)
some_mod:special_block × 8
another_mod:weird_block × 4
发送 $fix 1 将用 stone 替换（可指定替代方块）
```

### $fix

修复任务对应的方块错误，支持两类：

1. **世界差异**（`$verify <ID>` 检查发现的）— 重新放置被挖掉/替换的方块，恢复与投影一致（需游戏连接，执行 `setblock`）
2. **无法映射方块**（`$verify <ID> map` 检查发现的）— 替换为指定方块（默认 `minecraft:stone`），使这些方块也能被导入

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| ID | int | 是 | 任务 ID |
| 替代方块 | string | 否 | 替换无法映射方块的方块 ID（默认 `minecraft:stone`） |

**示例：**

```
$verify 1                     # 世界检查发现 3 个方块被挖掉
$fix 1                        # 重新放置这 3 个方块，恢复与投影一致
$fix 1 minecraft:oak_planks   # 用橡木板替换无法映射方块
```

修复后：

- 世界差异方块被逐个 `setblock` 重新放置（**等待响应并自动重试**，避免命令被限流丢弃）；重试仍失败的差异会**保留**，可再次 `$fix` 继续修复，直到全部干净
- 无法映射的方块被加入待导入列表（原位置），任务数据已更新，若尚未确认导入，直接发送 `$y` 即可用修复后的数据导入
- 再次 `$verify <ID>` 世界检查会显示全部一致

> **注意**：`$verify` / `$fix` 只能操作 `$create` 创建的任务。任务 ID 每次 `$create` 都会递增，重启脚本后任务存档清空。

### $status

查看当前导入进度，包括：

- 已完成百分比
- 当前阶段（清除空气 / 放置方块 / 等）
- 命令执行速度
- 预计剩余时间

### $author

显示作者信息。

## 亮点

- **大规模建筑支持** — 自动分割超大建筑，分区域导入
- **实时进度监控** — 随时查看导入速度和剩余时间
- **智能指令优化** — 自动合并相邻同种方块为 fill 指令
- **无需本地存档** — 通过 WebSocket 连接任意正在运行的世界
- **自动常加载区块** — 导入期间自动创建和删除 ticking area
- **空气层自动裁剪** — 检测并裁剪建筑底部的空白空气层，避免悬空与破坏地形
- **虚拟预览** — 粒子边框 + 实体标记，放置前确认建筑位置和大小
- **结构文件导出** — 一键导出 `.mcstructure`，可用结构方块预览放置
- **方块检查与修复** — `$verify` 检查世界与投影一致性（也可 `map` 检查映射错误），`$fix` 重新放置差异方块或替换无法映射方块
